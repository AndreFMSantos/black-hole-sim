# v0.8b — Flight interface (v0_6b-kerr-cuda; now `v0_8-flight-cuda` / `v3_1-kerr-cuda-ui`)

Uses the physical core of [08a-pilot](08a-pilot.md) (`bhs::pilot::Pilot`: Kerr timelike geodesic + thrust, double precision on the host) and the v0.7d Kerr kernel. The camera is no longer tied to a sphere: the pilot **falls** and **accelerates**; the kernel only receives, every frame, `(r, θ, φ_c, β, camera basis)`.

## Generalised camera (kernel)
`n' = −d'/‖d'‖` with `d' = fwd + x·right + y·up`, where `(fwd, right, up)` is an orthonormal basis expressed in the observer's `(e_r, e_θ, e_φ)` (axes of the boosted ZAMO) and `(x, y)` are the FOV tangents. The default basis is the usual one (`fwd = −e_r`, `right = +e_φ`, `up = −e_θ`) and gives `n' = (1, y, −x)/nrm`. `n'` goes through aberration (`observer_to_zamo`, v0.7d) and enters the trace as before.
**Regression:** the default look **stays byte-identical** (the 3 md5s of `tools/regress_v07d.sh`, generated before this generalisation, in `ctest`). The selftest adds: default basis vs `(1, y, −x)/nrm` to 2e-16 (the device contracts `1 + x² + y²` into an FMA, the host does not: that is why the *bit-for-bit* proof is the golden and not this comparison); rotated basis (yaw 90°, pitch 30°, roll 20°) vs the host formula to 4e-16, orthonormality to 4e-17 and central ray = `−fwd`.

## Modes and frame loop
`Orbit` (the existing one: mouse orbits, wheel = distance; nothing changed) and `Flight` (`--mode flight`, key **F** toggles). `--start orbit|zamo|infall` = initial velocity in the ZAMO: Keplerian circular (`lorentz::circular_beta`), at rest, or radial fall `−√(2/r)`; on entering flight it starts from the camera's (dist, θ, φ) position and on leaving it leaves the camera where the pilot is. Loop of each frame (host): read the keys → `Flight::step(dt_real)`: `thrust(accel, dtau)` if there is thrust, `advance(dtau)` with `dtau = dt_real × timescale` (`--timescale`, default 5 M/s; `,` `.` ×÷1.25) → fill `Params` (`r, θ, φ_c, β`, basis) → 1 sample → bloom/tone mapping → HUD → GL. If `captured()` (`r < r₊ + 10⁻³`): the simulation stops, the frame stays frozen, the HUD shows **"HORIZON: SIMULATION PAUSED"** in red, and **Backspace** restores the initial state.

## Controls (flight mode)
| Input | Action |
|---|---|
| mouse (drag) | look: yaw/pitch relative to the pilot, no pitch limit (basis rotations, no *gimbal lock*) |
| `Q` / `E` | roll (1.2 rad/s) |
| `W`/`S`, `D`/`A`, `Space`/`Shift` | thruster forward/back, right/left, up/down **relative to the view** (the sum of several is normalised to the current level) |
| `Ctrl` | brake: thruster opposite to the velocity relative to the ZAMO, with magnitude limited to `min(2×level, |β|/dτ)` (does not reverse direction in one step) |
| `+` / `-` | proper-acceleration level: `0.002·10^(i/3)`, i = 0…6 (0.002 … 0.2 c/M; default 0.02) |
| `,` `.` | time scale; `Z` pauses time (camera and thrust do not advance; the image converges); `H` HUD; `Backspace` resets; `PageUp/PageDown` exposure |
| `T B C O` `↑↓` `P` `G` | as in v0.7d (tone mapping, bloom, cinematic, observer, sky, precision, disk); `O`, `D`, `[ ]` only in orbital mode (the spin is part of the trajectory) |

## HUD (drawn in CUDA on the final frame)
**Embedded** 7×13 monospaced bitmap font (`hud_font.hpp`, generated by `tools/gen_hud_font.py` from Liberation Mono Bold, 1 bit; data only), scale `max(1, height/540)`, translucent background; lines starting with `!` in red. Content: mode, `a`, `r, θ, φ`, `r−r₊`, `r−r_ISCO`, `|β|`, `γ`, proper time `τ`, coordinate time `t`, `E, L, Q`, thrust level and time scale, and the **frequency shift of the central ray** (computed on the host with `kerr::trace` in double: if it hits the disk, `g = ν_obs/ν_emit` (Kerr × observer Doppler); if it escapes, `ν_obs/ν_∞ = (E'/E_zamo)·E_loc`; if it falls, "central ray: horizon"). Measured cost: 0 (118.9 vs 118.8 fps with `--nohud`). `--nohud` / key `H`; in `--shot`/`--video` use `--hud`.

## Performance (RTX 5080, 1896×1040 ≈ 1080p window, float, 1 sample/frame, measured with `--autoexit 300`, no input)
| Scene (a = 0.9) | full resolution | `--move-scale 0.5` |
|---|---|---|
| flight, r = 40, θ = 80° | **118.9 fps** (8.4 ms) | 387 fps |
| flight, r = 12, θ = 85° | 166 fps | 555 fps |
| flight, r = 6, θ = 85° | 168 fps | 558 fps |
| flight, r = 40, `--cinematic` | 109 fps | – |
| orbital mode r = 40 (reference, accumulates up to 128) | 98.9 fps | – |
`--move-scale s`: while the scene changes it renders at `s×` the resolution (buffers allocated once at maximum capacity, no reallocation) and upscales with a linear filter; when it stops, it restarts accumulating at full resolution. In flight the camera changes every frame (free fall), so progressive accumulation only happens with `Z` (or stopped). The HUD is drawn at the rendered size (it gets enlarged with `--move-scale`).

## Tests
`--selftest` (in `ctest`): + camera basis (3 cases above); **controls** (W accelerates ~0.02 c/M × 10 M: β_r = −0.209; Ctrl takes |β| to 1e-4 without reversing; yaw 90° puts `fwd` on the old `right` to 6e-17); **capture** (fall from r = 2.6: `captured()`, the next step changes nothing; `reset()` restores the initial state); **scripted flight** of 900 frames: no NaN, no capture, periastron 4.41, E and L (recomputed from the state, not just the stored ones) conserved between burns to 1.8e-15, and the kernel accumulator finite over the 300 rendered frames (96×54). 75 `core` tests + selftest green.

## Limitations
Orientation **without Fermi-Walker transport**: the basis is fixed in the local ZAMO's `(e_r, e_θ, e_φ)`, so on an orbit the camera "rotates" with the radial direction; to hold a fixed direction you have to roll/look. The simulation **stops** at the horizon (Boyer-Lindquist coordinates stop working); passing through the rotation axis makes the azimuth φ jump by π (the Pilot does not regularise) and the ZAMO has `ϖ → 0` there. The sky only has aberration (no Doppler/colour). Thrust is impulsive per frame (constant proper acceleration only in the limit of short steps). No mouse inertia or look acceleration. With `--move-scale` the HUD gets enlarged.
